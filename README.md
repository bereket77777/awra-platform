# React + Vite

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend using TypeScript with type-aware lint rules enabled. Check out the [TS template](https://github.com/vitejs/vite/tree/main/packages/create-vite/template-react-ts) for information on how to integrate TypeScript and Oxlint's TypeScript related rules in your project.

## Production deployment on Vercel

The project builds to `dist/` with `npm run build`. Vercel serves the static build over HTTPS, and `vercel.json` sends client-side routes back to the app entry point. The PWA manifest and service worker are generated by `vite-plugin-pwa` as part of the production build.

### Deploy from GitHub

1. Push the project to a GitHub repository and import it in the Vercel dashboard.
2. Keep the project root as the Root Directory. Set the Framework Preset to **Vite**, the Build Command to `npm run build`, and the Output Directory to `dist`. Use Node.js 22 or newer.
3. In **Settings → Environment Variables**, add the variables below for **Production** (and Preview if you want preview deployments to connect to Supabase). Values are supplied by your Supabase project and TURN provider:

   | Name | Value / purpose |
   | --- | --- |
   | `VITE_SUPABASE_URL` | Supabase project URL |
   | `VITE_SUPABASE_ANON_KEY` | Supabase publishable/anon key |
   | `VITE_TURN_URL` | TURN server URL, e.g. `turn:...` or `turns:...` |
   | `VITE_TURN_USERNAME` | TURN username |
   | `VITE_TURN_CREDENTIAL` | TURN credential |

   Supabase variables are required for sign-in, matchmaking, and call signaling. TURN variables are optional for compiling, but a working TURN service is strongly recommended for calls across restrictive mobile/campus networks. Use client-safe, preferably short-lived TURN credentials: all `VITE_*` values are included in browser code. Never put a Supabase service-role key or other server-only secret in a `VITE_*` variable.
4. Click **Deploy**. Every push to the connected branch will build and deploy automatically; redeploy after changing environment variables.
5. In Supabase **Authentication → URL Configuration**, set the Site URL to the production origin and add the Vercel production URL (and any custom domain) to the allowed redirect URLs.
6. Open the deployed HTTPS URL on a phone, grant microphone access, and install AWRA from the browser's install/add-to-home-screen action. Check the browser's application/storage tools for the manifest and active service worker if troubleshooting.

### Deploy with the Vercel CLI

1. Install the CLI with `npm install --global vercel`, then run `vercel` from the project root and follow the prompts to link or create a project.
2. Add the same environment variables listed above with `vercel env add <NAME> production` (repeat for each variable; enter values at the prompt).
3. Deploy with `vercel --prod`. After changing environment values, deploy again with `vercel --prod`.

The service worker caches the built app shell; voice calling, authentication, and matching still require a network connection to Supabase and the configured signaling/media services.

## Local development

- `npm run dev` starts the Vite development server.
- `npm run build` creates the production site in `dist/`.
- `npm run preview` serves the production build locally.
- `npm run lint` runs Oxlint.

Create a root `.env.local` for development using the same `VITE_SUPABASE_*` and optional `VITE_TURN_*` names above. Do not commit environment files.
